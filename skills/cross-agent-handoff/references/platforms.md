# 按需加入任意平台

只有当前模式涉及平台扩展或安装入口判断时读取本文件。

先尝试让目标平台读取同一份通用 Markdown。交接本身不要求启动或控制目标平台，也不要求所有项目安装原生 Skill；入口已配置、原生加载和真实接续分别核验。

## 触发与边界

| 输入或现场 | 行为 |
| --- | --- |
| “把 Gemini CLI 也加进上下文继承” | 显式扩展，识别项目事实源并核对该平台机制 |
| “以后要在另一个平台接着做” | 明确目标后准备相应入口；未命名且影响结果时只问平台名称 |
| 正在切换平台，接收端确实缺少必要入口 | 识别接入缺口，在已有授权内补足；缺少授权则给具体改动建议 |
| 平台已有可用的共享入口 | 复用，不再加一份配置 |
| 只问哪个模型更好，或扫描到某平台已安装 | 不创建适配器 |

## 生命周期事件

本版没有注册生命周期回调或后台监听。只有宿主实际提供可靠事件、可确认它对应当前任务且用户允许自动保存时，才能按该请求保存交接。没有这些条件就保留手动用法，不因猜测上下文比例、编辑次数或日志里的历史压缩标记声称自动触发。

真实事件验证应记录宿主、事件、实际作用域与回执；手动发一句“准备换平台”不能当作事件适配已通过。不为测试事件而修改全局配置或批量建立平台适配器。

## 接入流程

1. 确定平台及宿主形态：CLI、IDE、桌面或网页，以及项目文件是否可访问。平台名字相同，不代表这些形态共享安装路径和权限。
2. 先读项目现有入口和目标平台配置；用实际版本、宿主帮助或当前官方文档确认自动加载机制、语法和作用域。未知平台不猜文件名。
3. 若原生能读现有公共入口，优先直接复用。若确实需要适配，将下面的薄引用合并到实际入口；保留已有内容、编码与权限，写前重读。不为接入改动其他项目或全局配置。
4. 入口只指向当前项目中真实存在、接收端能访问的路径。下面的 `HANDOFF.md` 是默认示例，项目用了别的路径就替换成实际路径。
5. 先查文件和引用能否解析；再在目标宿主新会话中明确调用，确认它能读到当前目标、未完事项和下一步。无法运行宿主时报告 `HOST_LOAD_NOT_RUN`，不自动启动付费模型或尝试绕过权限。

可合并的通用入口片段：

```markdown
## 项目交接

需要跨 AI 平台或会话接续时，先读本项目 HANDOFF.md 及其必要引用，核对实际文件与验证状态，再继续用户已授权的未完任务。
准备切换平台、暂停或结束阶段时，更新同一份交接文件。
用户要求将其他平台加入上下文继承，或发现实际跨平台接续缺少入口时，按需接入；入口仅引用同一份事实，不另存平台专属进度。
```

片段不代替完整 Skill。需要自动发现三种模式时，在该宿主支持的位置安装完整 Skill；仅添加此片段时报告为“入口已配置”。

## 已核对的入口机制

以下仅表示 **2026-10-29 已阅读官方文档**，不是本包的宿主运行实测。

| 平台 | Skill 的项目位置 | 共享规则入口与注意点 |
| --- | --- | --- |
| Codex | `.agents/skills/cross-agent-handoff/` | `AGENTS.md`；同级 override 或更近层规则可能影响加载 |
| Claude Code | `.claude/skills/cross-agent-handoff/` | 先检查是否已读取 `AGENTS.md`；需要 Claude 专属入口时，在已有 `CLAUDE.md` 中按官方机制引用公共入口即可 |
| 其他平台 | 运行时核对官方机制 | 能读文件则引用同一交接；不能自动加载则显式读取或由用户粘贴材料 |

Claude Code 对 `AGENTS.md` 的直接支持有版本与设置条件，不把所有版本都当成支持，也不强制每个版本新建 `CLAUDE.md`。官方文档允许需要时用 `@AGENTS.md` 引用；合并前检查是否已经引用，避免重复。

官方依据：

- [OpenAI：Skills 与项目位置](https://learn.chatgpt.com/docs/customization/overview)
- [OpenAI：AGENTS.md 加载规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- [Claude Code：Skills](https://code.claude.com/docs/en/skills)
- [Claude Code：项目记忆与共享 AGENTS.md](https://code.claude.com/docs/en/memory)

## 对扩展结果的报告

分别说明：目标平台、采用的入口、引用的事实源、实际改动、静态检查结果、宿主加载是否实测、真实接续是否完成。不要用一个“支持”覆盖所有层次。

用户需要 Gemini CLI、Cursor、Copilot、Antigravity 或其他工具时都可以走这个流程。无需先把平台写进固定名单；也不宣称这些平台已经逐一验证。
